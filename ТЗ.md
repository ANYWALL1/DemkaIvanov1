Вот подробное техническое задание (ТЗ) для разработки WPF-приложения на C#, составленное на основе предоставленных требований. Вы можете передать это описание исполнителю (или ИИ-ассистенту) в качестве исчерпывающей инструкции.

### Общая архитектура и требования к коду

* **Паттерны и структура:** Логика представления (UI/формы), бизнес-логика (проверки, расчеты) и логика работы с базой данных (SQL-запросы, Entity Framework/ADO.NET) должны быть разделены на независимые модули.


* **Классы:** Каждая сущность должна быть представлена отдельным классом. Классы должны быть компактными и выполнять строго одну функцию (Single Responsibility).


* **Именование:** Использовать стиль `CamelCase` для C#. Запрещено использовать стандартные имена элементов (например, `Form1`, `button3`), имена должны отражать суть. Название самого приложения должно включать имя компании-заказчика.


* **Обработка ошибок:** Приложение не должно аварийно завершаться при непредвиденных ошибках. Необходимо уведомлять пользователя об ошибках валидации (неверный тип данных, размер поля) через информативные окна сообщений с пиктограммами.


* **Файловая система:** Использовать относительные пути для изображений, чтобы приложение работало при перемещении папки.



### Дизайн и стилизация (согласно Руководству по стилю)

* **Шрифт:** Везде использовать шрифт `Tahoma`.


* **Логотип и иконка:** Для приложения должна быть установлена иконка. На всех экранных формах в заголовке должен присутствовать логотип компании без искажения пропорций и цветов.


* **Цветовая схема:**
* Основной фон: Белый `RGB(255, 255, 255)`.


* Дополнительный фон: `RGB(225, 228, 255)`.


* Акцентный цвет (для целевых действий): `RGB(255, 74, 109)`.




* **Компоновка:** Окна должны иметь минимальный размер и масштабироваться. При увеличении окна должна увеличиваться контентная часть (например, списки). Должен работать переход по клавише TAB.



### Экран 1: Главное окно (Список услуг)

* **Режимы доступа:** По умолчанию открывается клиентская зона (просмотр). Для активации режима администратора нужно ввести код `0000`. Администратору открываются функции: добавление, редактирование, удаление, запись клиента, просмотр ближайших записей.


* **Карточка услуги:** Должна отображать: наименование, стоимость, длительность, миниатюру главного изображения, размер скидки.


* **Отображение скидки:** Если скидка > 0, фон карточки услуги должен быть светло-зеленым. Основная цена должна быть перечеркнута, а рядом выведена итоговая цена (с учетом скидки, а не сам размер скидки).


* **Сортировка:** По стоимости (возрастание/убывание). Логика сортировки должна быть реализована кодом (в бизнес-логике), а не встроенными функциями UI-элементов.


* **Фильтрация:** Выпадающий список по скидке: от 0 до 5%, от 5% до 15%, от 15% до 30%, от 30% до 70%, от 70% до 100%. Диапазон ищется по принципу `min <= x < max`. Должен быть пункт «Все» для сброса. Фильтрация применяется в реальном времени.


* **Поиск:** Текстовое поле для поиска по названию и описанию в реальном времени (без кнопки "Найти"). Поиск и фильтрация должны работать совместно.


* **Пагинация/Счетчик:** Внизу окна выводить строку вида "230 из 450", которая обновляется при фильтрации и поиске.


* **Удаление (только Админ):** Запрещено удалять услугу, если на нее есть прошлые или будущие записи. Если записей нет, услуга удаляется вместе с ее дополнительными фотографиями. Перед удалением запрашивать подтверждение.



### Экран 2: Окно добавления/редактирования услуги (только Админ)

* **Поля данных:** Название, стоимость, длительность, описание, скидка, основное изображение.


* **Поведение окна:** Запрещено открывать более одного окна редактирования одновременно. После сохранения данных список услуг в главном окне должен обновиться.


* **Редактирование:** Поля заполняются текущими данными. Поле ID доступно только для чтения.


* **Добавление:** Поле ID отсутствует (генерируется БД).


* **Валидация:**
* Название услуги должно быть уникальным (проверка на дубли при добавлении).


* Длительность не более 4 часов и не отрицательная.




* **Работа с изображениями:**
* Можно добавить/заменить главное изображение (показывать миниатюру).


* Можно добавить одно или несколько дополнительных изображений (показывать миниатюры), а также удалять их.


* Выбранные файлы изображений должны физически копироваться в директорию проекта. В БД сохраняются пути до файлов.





### Экран 3: Окно записи клиента на услугу (только Админ)

* **Информация об услуге:** Выводить наименование и длительность в минутах (read-only).


* **Выбор клиента:** Выпадающий список (ComboBox), содержащий ФИО клиентов из БД.


* **Дата и время:**
* Дата выбирается через UI-календарь (DatePicker).


* Время начала вводится в текстовое поле, разрешены только цифры и двоеточие. Поле валидируется на корректность времени.




* **Расчеты:** Время окончания должно рассчитываться и отображаться автоматически на основе времени начала и длительности.


* **Сохранение:** Данные пишутся в таблицу записей в БД.



### Экран 4: Ближайшие записи (только Админ)

* **Назначение:** Окно для просмотра записей на *сегодня* и *завтра*.


* **Сортировка:** По умолчанию по дате и времени (по возрастанию).


* **Карточка записи:** Наименование услуги, ФИО клиента, Email, телефон, дата и время записи, оставшееся время до начала (в формате "X часов Y минут").


* **Цветовая индикация:** Если до начала осталось менее 1 часа, оставшееся время выделяется красным цветом.


* **Автообновление:** Окно должно автоматически обновлять данные каждые 30 секунд (использовать `DispatcherTimer`).
